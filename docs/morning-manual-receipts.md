# MorningStay manual collection

Morning detail now shows a collapsed billing section and a separate explicit
manual collection action for operations owners and enabled Google managers.
Choose bank transfer or cash, enter the full SAR amount and actual receipt time
(Riyadh), optional transaction/reference and note, and confirm actual receipt.

An additive `MorningOfflineReceipt` table records amount, method, reference,
receipt time, recording time and operator. This is an administrative receipt,
not a bank API verification or a successful HyperPay transaction. No guest record
is changed by deploying this feature. No card charge, Hostaway write, invoice,
loyalty award, guest message or communication event is generated by recording it.

Property/stay row locks match checkout creation. Unresolved or successful card
attempts block manual collection; failed/cancelled attempts permit it. The amount
must match the stay, cancelled/already paid stays are rejected and exact retries
are idempotent. The signed payment link cannot initiate another payment once paid.
Late card results preserve manual receipt money: a second successful capture puts
the stay into review; a failed card response cannot reopen a paid stay.

Tests use synthetic records and fake providers, cover role/CSRF checks, invalid
amount/date/confirmation, duplicates, closed links and late results. PostgreSQL
CI also exercises parallel receipt requests. Existing responsive checks expand
the initially collapsed billing section before testing address suggestions.

Deploy only after the quality gate. Standard build applies migration 0029 before
serving the new code. Rollback code without dropping the receipt table or its
financial records; do not reverse this migration after use.
